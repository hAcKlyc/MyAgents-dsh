# Assurance domain

This domain separates what is implemented, what is compatible, what is safe to claim and which exact bytes have evidence.

## Read by task

| Task | Start here | Then read |
| --- | --- | --- |
| Decide whether a capability can be advertised | [Compatibility and capability truth](./compatibility-and-capability-truth.md) | the affected implementation guide and compatibility manifest |
| Review trust, secrets, permissions or containment | [Security and trust boundaries](./security-and-trust-boundaries.md) | the affected boundary/execution guide |
| Build or transfer an accepted Runtime/handoff | [Verification, artifacts and handoff](./verification-artifacts-and-handoff.md) | exact manifests, external acceptance record and builder scripts |

## Domain boundary

Assurance documents explain claim rules and evidence chains. They do not promote a release: exact manifests, executable campaigns and the trusted release record must agree.
