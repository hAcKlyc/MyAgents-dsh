# MyAgents 集成 DSH：三档权限体验 PRD

> 状态：实施与验收依据
> 日期：2026-09-29
> 范围：MyAgents 内置的 MyAgents-dsh Runtime；不改变其他 Runtime 的权限模式

DSH 集成尚未正式发布。本需求直接替换当前集成协议、配置和权限值，**不迁移、不兼容旧 DSH Runtime 的会话或权限数据**；旧值在新版本中不得被静默解释成新模式。其他 Runtime 的既有数据与模式不在此次清理范围内。

本次交付还包括 MyAgents 客户端集成：移除 DSH 会话模式菜单中的“已授权操作”入口及对应界面；移除 DSH Agent 设置的“技能 Skills”页顶部整块“当前会话组件可用性”卡片，不影响真正的技能设置。MyAgents-dsh 以 **0.1.9** 版本完成开发、原生构建、PR/CI、合并和 GitHub Release；MyAgents 在当前 `dev/intergration_myagents-dsh` 集成分支集成该版本并提交，不另起正式发布。必须通过 MyAgents 客户端实际交互验收三档权限和两处界面变化，不能只以单元测试或协议测试代替。

## 1. 目标

将 MyAgents 集成 DSH 的产品权限入口收敛为三个模式。用户选择的是完整的执行预设，而不是分别配置工具审批、文件范围和沙盒。模式由 MyAgents 持久化和展示，MyAgents-dsh 在实际执行时落实；上游 DeepSeek Harness（下称 dsh）提供可复用的工具和沙盒能力。

本需求采取**开放读取、分级限制写入**的体验：三个模式均允许使用本机用户有权读取的工作区外文件。前两档的 `workspace-write` 管的是默认写入范围，不是读取范围。产品副标题按第 2 节的指定文案呈现；其简短措辞不能代替下文的具体行为定义。

## 2. 产品文案与模式语义

| 模式名称 | 副标题（逐字采用） | DSH 本地文件工具与 Shell 的默认写入范围 | 审批及越界写入 |
| --- | --- | --- | --- |
| 请求批准 | 工作区内行动，使用工具需审批 | 当前工作区及沙盒允许的系统临时目录 | 指定工具调用需审批；被沙盒拒绝的工作区外写入，可由 Agent 针对该次操作发起一次提权审批。用户拒绝或审批不可用时保持拒绝。 |
| 工作区自主 | 工作区内无限制，无需审批 | 当前工作区及沙盒允许的系统临时目录 | 不弹出工具或沙盒提权审批；工作区外写入直接失败，不能自动升至完全自主。 |
| 完全自主 | 无限制使用电脑与互联网，无需审批 | 本机当前用户的操作系统权限范围 | 无工具或沙盒提权审批；不施加工作区写入围栏。 |

这三个副标题是产品展示文案。其中“工作区内行动”和“工作区内无限制”描述 **DSH 本地文件工具与 Shell 的默认写入边界**：两个模式仍允许读取工作区外文件，请求批准模式还允许用户明确批准某一次越界写入。MCP、Host 扩展工具和内部 CLI 不在此写入围栏内。详细说明、拒绝结果和审批卡片必须把适用范围讲清，不能暗示读取或所有外部工具都受工作区限制。

“完全自主”表示 MyAgents 不再施加工作区写入限制、交互审批或额外的产品模式网络限制；它不授予超过登录用户、系统隐私权限、Provider 凭据或网络服务本身所允许的能力。Web 工具现有的 URL 有效性和执行安全检查仍按其自身契约工作。

## 3. 工具审批规则

### 3.1 请求批准

- `read`、`read_image`、`write`、`edit`、`glob`、`grep`、`ls` 的普通调用不弹工具审批。用户明确指定 `Read`、`Write`、`Edit` 免审批；只读搜索与列目录按同一低打扰原则处理。它们仍受写入沙盒和其他工具自身约束。
- `bash` / `pwsh` 调用需审批。通过工具审批后仍在 `workspace-write` 沙盒中运行；批准“运行命令”**不等于**批准在工作区外写入。
- `web_fetch` / `web_search` 等向外部服务发起请求的工具，以及 MCP / MyAgents Host 扩展工具，需按现有权限交互请求审批。普通工具审批保留精确的“始终允许”，仅在当前 Session 生命周期内生效；不提供“已授权操作”管理界面。沙盒越界提权不提供“始终允许”。
- `AskUserQuestion` 本身是问答，不应再套一张“允许提问”的审批卡。Plan 审阅也保留其独立的交互语义。其余任务/子 Agent/后台工作工具按工具实际副作用分类，不因为“这是内置工具”就默认为全部放行。
- 当 `write`、`edit` 或 Shell 写入被工作区沙盒拒绝时，Agent 可按上游沙盒的同次拒绝证据，提交一次明确的更高范围请求。用户批准只授权这次精确的重试；不改变 Session 的常驻模式，也不建立“始终允许越界写入”规则。普通 Shell 审批和越界写入提权可能依次发生，卡片须区分两者。

### 3.2 工作区自主与完全自主

- 两档均不弹普通工具审批。工作区自主仍保留 `workspace-write` 的硬写入边界；任何 `sandbox_permissions` 提权请求均自动拒绝，不得因工具审批的 bypass 设置而被间接放行。
- 完全自主使用 `danger-full-access` 的写入语义；Shell 和文件工具不受工作区写入边界限制。网络请求不因产品权限模式而等待审批。
- 权限模式不隐藏工具，也不取消工具/Provider 的输入校验、身份校验、取消、超时或失败处理。

## 4. 写入边界与适用工具

1. **本地文件工具**：`write` / `edit` 在执行前对最终目标路径应用模式写入策略。`read` / `read_image`、搜索和列目录不再以“必须位于当前工作区”为读取条件。路径规范化、符号链接目标及执行前身份复核仍保留。开放读取应是显式策略语义，不用把 `/`、盘符根目录或用户目录塞进读取白名单模拟。
2. **Shell**：前两档使用带进程沙盒的 Bash/PowerShell 执行器，使命令及其子进程的普通本机文件写入受到 `workspace-write` 约束；第三档不启用该写入围栏。Shell 可以选择工作区外的可读目录作为工作目录；仅限制启动工作目录不能满足本需求。
3. **沙盒临时目录**：沿用上游 `workspace-write` 定义的临时写入区域。因此“工作区外全部不能写”不是准确的技术表述；产品详细说明应展示临时目录例外。
4. **MCP / Host 扩展工具**：不纳入本需求的工作区写入围栏。它们可能在别的进程、服务或机器上执行，不会天然继承 DSH Shell 的系统沙盒；自身已有的权限与能力约束仍有效。请求批准模式按工具调用审批；工作区自主和完全自主不因本模式弹审批。扩展工具可能在工作区外产生写入，产品不能把 DSH 原生工具的沙盒效果宣传为所有工具的保证。
5. **MyAgents 内部 CLI**：不纳入本需求的工作区写入围栏。它通过 Shell 可调用，但其中转交 Host 执行的能力不受 Shell 文件沙盒自然约束；这些能力沿用各自已有的授权。请求批准模式仍审批启动它的 Shell 调用；该审批不代表内部 CLI 的后续写入受工作区围栏约束。工作区自主模式下调用内部 CLI 无本模式审批或额外写入限制。

## 5. 三个仓库的职责

| 仓库 | 责任 |
| --- | --- |
| MyAgents | 展示并持久化三个模式，确定每个 Product Session 的期望模式和工作区；通过现有 SessionEngine DSH adapter 下发，展示普通工具审批与沙盒提权审批，并只在 Runtime 确认后显示有效状态。其他 Runtime 的模式列表保持独立。 |
| MyAgents-dsh | 将产品模式编译为工具审批策略和写入沙盒策略；在同一工具执行管线落实本地文件、Shell 与子 Agent 的写入边界，以及扩展工具的调用审批；提供有效策略和拒绝原因的可诊断事实。 |
| 上游 dsh | 提供 `workspace-write` / `danger-full-access` 沙盒策略、受限文件系统和 Bash/PowerShell 执行器以及单次提权机制。优先通过公开的组合/扩展接口复用，确实无法表达的语义才考虑受控的上游补丁。 |

产品模式可以按两个维度编译，而不把“无需审批”解释成“不受沙盒约束”：“请求批准”＝按需审批 + `workspace-write`；“工作区自主”＝免审批 + `workspace-write` 且禁止提权；“完全自主”＝免审批 + `danger-full-access`。

新协议只接受以下 DSH 专属稳定值；展示文案仍以第 2 节为准：

| 产品模式值 | 普通工具审批 | 文件效果沙盒 | 沙盒提权审批 |
| --- | --- | --- | --- |
| `approval-required` | `default` + 精确免审工具 | `workspace-write` | `ask`，仅本次获批重试 |
| `workspace-autonomous` | `bypassPermissions` | `workspace-write` | `never` |
| `full-autonomous` | `bypassPermissions` | `danger-full-access` | `never` |

规划状态独立保存为 `normal` / `plan`，不能作为第四个权限值。普通工具的 `bypassPermissions` 只跳过审批；沙盒写入限制由另一执行层继续生效。

### 5.1 黑白名单与执行层方案

这三档不需要一份由 MyAgents 维护的“禁止访问哪些目录”黑名单。**读取**采用显式的 `local-user` 范围，具体访问仍受操作系统权限约束；**写入**在前两档采用一个正向允许范围：工作区根目录与上游沙盒定义的临时区域，其余位置默认拒绝。第三档不施加产品写入范围。对整个电脑使用有限黑名单无法等价表达“只有工作区可写”，也不能阻止 Shell 子进程写入。

当前协议的 `allowedReadRoots` / `allowedWriteRoots` 是 MyAgents-dsh 自加的文件工具白名单模型：MyAgents 在 `initialize` 中发送 `[workspace]`，MyAgents-dsh 的文件工具据此逐次判断，且根目录必须列入两个数组、允许根目录不能覆盖 Runtime 自有目录。这些字段不能直接表达“开放读取”或“完全自主写入”。实施时**删除这套字段及其沿线硬判断**，直接用明确的产品模式与工作区身份编译唯一的上游写入沙盒策略；不要叠加新黑名单、第二套路径 guard 或旧数据兼容分支。保留文件身份、并发和检查点等与白名单无关的既有职责。

| 能力/决策 | 提供与执行层 |
| --- | --- |
| 模式选择、展示、Session 期望值、审批 UI | MyAgents Host；只下发三档产品模式及工作区身份，不下发独立的读写根目录策略。 |
| 普通工具是否需审批 | MyAgents-dsh 的 ProductPermissionService，经现有 DSH `ctx.tools` 管线和 Host interaction 端口执行；按模式映射到 `default` + 精确免审工具，或 `bypassPermissions`。 |
| 每次文件效果的共同模式与工作区根目录 | 上游 dsh `ctx.sandboxPolicy`；MyAgents-dsh 在安全的 Session/turn 边界把产品模式映射为 `workspace-write` 或 `danger-full-access`。 |
| `write` / `edit` 的写入围栏 | 上游 dsh `SandboxedFileSystem`（`@deepseek-ai/dsh-fs-sandbox`），与 MyAgents-dsh 现有单一 Product 文件系统能力合成；其读操作不受沙盒写入模式限制。Product 文件工具取消旧根目录的重复授权判断，保留路径身份、检查点等自身职责。不能同时挂两个 `ctx.fs` Provider。 |
| Bash / PowerShell 及其子进程的写入围栏 | 上游 dsh `SandboxBashExecutor` / `SandboxPwshExecutor` + `LocalSandboxProvider`；替换现有本地执行器，实际执行时按每次调用的沙盒策略封装进程。前两档若无可用沙盒，拒绝命令而不降级裸跑。 |
| 单次越界提权 | 上游 dsh 文件工具与 Shell 的 `sandbox_permissions`、`ctx.approval` 机制；MyAgents-dsh 在现有 Host interaction 通道增加可辨识的沙盒提权请求及审批卡。当前 ProductPermissionService 的监听器只识别普通工具权限的 pending 请求，不能直接把新请求送进去当作普通授权。“请求批准”允许本次获批重试，“工作区自主”将沙盒审批策略置为 `never`。 |
| MCP / Host 扩展工具及内部 CLI | 不纳入本需求的工作区写入围栏，不通过新模式附加文件路径限制；各自已有的能力约束继续生效。普通工具审批也不能冒充文件写入围栏。 |

此处复用上游的**策略与执行能力**，不是在 MyAgents UI 里实现路径黑名单，也不是用 `sandbox_permissions` 工具参数当作唯一防线。参数只发起一次有审计的更高范围请求；真正阻止文件工具和 Shell 写入的是各自执行层。模式切换要在没有活跃工具的安全边界完成；产品权限配置、上游 sandbox mode 和 approval policy 要作为同一有效模式发布，不能出现半切换状态。当前 Product 子 Agent 会把上游审批策略设为 `ask`；实施时必须改为继承父 Agent 的有效模式，不得把“工作区自主”的 `never` 改回可审批。根/子 Agent 需得到同一有效边界。

## 6. 与现状的差距

- MyAgents 目前对 DSH 展示 `auto`、`plan`、`fullAgency`，其中 `plan` 是规划状态，不应继续作为这三档权限之一。直接替换 DSH 专属模式值和协议形状；旧 DSH 会话/权限数据不迁移，恢复入口遇到旧形状时给出明确不可恢复结果。
- MyAgents 当前给 DSH 的读、写根目录都只有工作区。因此 `read_image` 无法直接读取 Downloads；新体验要求取消**读取**的工作区白名单，同时保留前两档写入围栏。
- MyAgents-dsh 当前使用本地文件系统和本地 Shell 执行器；上游进程沙盒包虽在依赖中，但并未启用，文件沙盒包尚未接入当前构建。把模式名改成 `workspace-write` 本身不会约束文件工具或 Bash。
- 现有 `acceptEdits` 会放行 Web 工具，不符合“请求批准”的对外操作需审批。新方案以直接的三档产品模式和工具权限类别实现审批表；文件读写等低副作用类别自动放行，Web 等对外调用在“请求批准”中审批。
- DSH 的执行环境当前在初始化时固定读写根目录，审批配置则可独立更新。新协议移除这组可变根目录授权后，Host 保存用户选择，下一条 query admission 前由现有 Session 配置 owner 协调：更新 Product 工具权限、上游 Session sandbox mode 与 approval policy，再确认有效模式后开始新 turn；进行中的工具调用不切换权限，也不因设置变化中断。

## 7. 验收场景

1. 在三个模式下，`read_image`、`read` 和搜索均能读取本机用户有权访问的工作区外文件；不要求先复制进工作区。
2. 请求批准：工作区内 `write` / `edit` 不触发普通工具审批；Bash、Web 和 MCP/Host 外部调用按对应规则审批。拒绝普通工具审批时工具不执行。
3. 请求批准：文件工具或 Bash 尝试在工作区外写入时，先得到可识别的沙盒拒绝；针对被拒绝的同次操作请求提权，用户批准后仅该次重试可以写入。拒绝、取消或审批不可用时不写入，也不改变常驻模式。
4. 工作区自主：工作区内文件工具和 Shell 写入无需审批；工作区外写入被拒绝，且无审批卡、无静默提权。系统临时目录按沙盒约定处理。
5. 完全自主：文件工具和 Shell 可在当前用户系统权限允许的位置写入，无产品模式审批；可通过既有 Web/网络路径访问互联网。
6. 子 Agent 与根 Agent 继承同一有效模式；执行中切换不打断当前 turn，下一条 query 才采用新模式。连续按“请求批准 → 工作区自主 → 完全自主 → 请求批准”在同一 Session 往返切换，最后一轮仍须正常发起 Bash 审批，不能把新轮次误认成旧授权修订。停止/恢复、Shell 后台任务、符号链接重定向均不得出现“UI 显示旧模式而工具已按新模式执行”的状态。切换时 DSH 原生审批策略通知不能使会话误入恢复状态。
7. macOS、Windows、Linux 分别对文件工具和实际 Shell 沙盒做本机验证；沙盒不可用时不能静默改成无限制执行。平台能力声明只依据对应平台的实际验证结果。
8. MyAgents 的 DSH 会话模式菜单不再显示“已授权操作”及其管理对话框；技能页顶部不再出现“当前会话组件可用性”卡片，原有技能列表与设置继续可用。
9. 在 MyAgents 客户端中实际切换并运行三档模式，验证工作区外读取、工作区内外文件与 Shell 写入、请求批准与拒绝、单次提权、工作区自主的自动拒绝及完全自主；截图对应的两处界面也通过客户端实际操作确认已删除。
10. 完成 MyAgents-dsh 0.1.9 的版本文件、生成契约、回归测试、原生 handoff、PR/CI、主分支合并、四平台 tag 构建及 GitHub Release；核对 Release 的清单、四平台资产与来源信息。MyAgents 消费对应正式版本，构建/测试通过后提交在当前集成分支；保留该分支已有的其他改动，不覆盖或夹带用户文件。

## 8. 已确定的适用边界

- **扩展能力**：工作区写入围栏只覆盖 DSH 本地文件工具及 Shell。MCP、Host 扩展工具和内部 CLI 按第 4 节执行，不纳入本需求的写入围栏；在工作区自主模式下，这些能力可能在工作区外产生效果。
- **网络**：三档均可使用网络工具；请求批准模式的对外工具调用需审批，工作区自主与完全自主不审批。本需求不增加按模式断网或网络沙盒。

## 9. 非目标

- 不增加读取路径黑名单或工作区只读隔离；读取工作区外文件是本需求的明确行为。
- 不重做其他 Runtime 的权限模式，也不把 DSH Plan 状态当作第四档权限。
- 不用提示词、工具参数检查或 Shell 命令字符串解析代替写入沙盒。
- 本文不宣称上述目标已经实现；实施后需同步更新受版本控制的架构、模块技术文档和真实产品文案。
